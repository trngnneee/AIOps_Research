# Evidence-backed thesis writing

Read `AGENTS.md`, the requested artifact, current roadmap, relevant source notes and actual results. Follow the user's language and institutional template; default to Vietnamese Markdown while retaining technical terms. Ask only for requirements that materially affect the requested artifact and cannot be found locally.

- Build the argument around problem, existing evidence, unresolved issue, RQ, method and evaluation. Organize related work by differences that matter to the RQ rather than a sequence of disconnected paper summaries.
- Verify each substantive claim against its actual source/version and location. Reading notes and findings are leads, not substitutes for checking the paper. Record inaccessible sources and unsupported claims explicitly.
- Separate planned work from completed experiments. Report denominators, independent units, conditions, uncertainty and budgets with quantitative results. Do not turn pilot trends into established general findings.
- Distinguish association from causal evidence, task success from valid reasoning, and a candidate contribution from demonstrated novelty. Include close prior work, negative findings and limits on generalization.
- Reuse the existing bibliography format. Verify title, authors, year, DOI/arXiv ID and version before adding a reference. Do not fabricate BibTeX fields or cite a paper solely because its title sounds relevant.
- Preserve the user's approved ideas and existing edits. Change the requested section, identify substantive added interpretations, and avoid silently rewriting research decisions or upgrading the strength of claims.

Deliver the requested prose plus a concise unresolved-evidence list when needed. For an audit, list claim, source location, support status, and correction. If results are missing, write an explicitly planned evaluation or mark what is needed; never manufacture a results section. Write only when asked, using the existing artifact or a descriptive file under `research/`.
